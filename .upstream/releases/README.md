# 发布清单（`.upstream/releases/`）

本目录存放**每个正式版一份的发布说明归档**，文件名 `<tag>.md`（如 `wcpe-v1.17.20.md`）。

## 为什么要进仓库

发布说明曾经在 CI 里按 `上一版..本版` 的**提交区间**现生成，而本仓库为插补丁会重写队列：
上一版 tag 脱离主线后，区间退到共同祖先，把上一版已发布的提交重复算进新版（实测 1.17.16~1.17.19
每版 78%~93% 的条目是「同标题、不同 SHA」的重写副本）。

现在改为：清单在**发版前**生成、随 tag 一起进历史，CI 只校验并发布它。清单本身就是那一版的发布说明，
事后可逐字复核，不依赖运行时重算，也不受队列重写影响（它按提交 trailer `Patch-Name` 的补丁面做集合差）。

## 生成与校验

```bash
# 发版前：生成并落盘 .upstream/releases/<tag>.md（同时打印一份到终端）
bash scripts/gen-release-notes.sh --tag wcpe-v1.17.20

# 以普通提交（元数据段）提交清单
git add .upstream/releases/wcpe-v1.17.20.md
git commit -m "docs: 补 1.17.20 的发布说明归档"

# 自检：清单缺失或与重算结果不一致 → exit 1
bash scripts/gen-release-notes.sh --check wcpe-v1.17.20
```

顺序不能反：**清单必须在打 tag 之前提交**。CI 的 `--check` 比对的是 tag 那份树里的清单，
所以 tag 之后再补提交是无效的——必须删掉 tag、补清单提交、重新打同一个 tag（Release 作业会以
`::error::` 失败并给出提示）。

## 禁止手改

清单是确定性输出（无时间戳、无生成者、无随机序），`--check` 逐字比对重算结果。**手改过就校验不过**。
内容不对时该改的是队列或补丁标题，不是这里——改完重新 `--tag` 生成一遍。

## 生效范围

| 版本 | 发布说明在哪 |
|---|---|
| `wcpe-v1.17.20` 起 | 本目录的 `<tag>.md`（随 tag 提交，CI 校验后发布） |
| 1.17.19 及更早 | 没有清单，仍以 GitHub Releases 上已发布的正文为准（这些版本的补丁没带 `Patch-Name`，不回填） |

## 文件命名

`<tag>.md`：tag 前缀原样保留（`wcpe-v1.17.20.md`），不要加日期后缀、不要把版本号改写成别的形式。
CI 与脚本按 `$WCPE_RELEASE_DIR/<tag>.md` 定位，目录默认就是本目录。
